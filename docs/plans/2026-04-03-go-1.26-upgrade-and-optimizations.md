# Go 1.26 Upgrade and Codebase Optimizations

**Status:** COMPLETED

## Summary

Upgrade the project from Go 1.24 to Go 1.26 and apply relevant optimizations from Go 1.25 and 1.26. The upgrade yields significant automatic performance wins (Green Tea GC, faster allocations, container-aware scheduling) plus a few concrete code-level improvements.

## Background

This is a ~2,500 LOC HTTP proxy service that:
- Accepts `GET /v1/search?q=...` requests
- Queries a SearXNG backend, collects results
- Sends results to an LLM for synthesis
- Returns structured JSON with answer and cited sources

The codebase is clean, well-structured, and uses Go 1.24 patterns. It runs in containers (distroless image) on Kubernetes.

## Phase 2: Automatic Performance Wins (zero code changes)

These come for free with Go 1.26 and require no code changes:

### 2.1 Green Tea Garbage Collector (default in 1.26)

Go 1.26 enables the Green Tea GC by default. It improves marking and scanning performance for small objects through better locality and CPU scalability. Expected: **10–40% reduction in GC overhead**.

This matters for this project because:
- The service processes many small allocations per request (JSON decode/encode, HTTP response bodies, string operations in prompt building)
- Each search-synthesis cycle creates short-lived objects across searx, proxy, and llm packages

### 2.2 Faster Small Allocations (< 512 bytes)

Go 1.26's compiler uses size-specialized allocation routines for objects under 512 bytes, yielding **up to 30% faster allocations**. This benefits the hot path: `synthesisPayload`, `searx.Result`, `http.Request`, `httptest.ResponseRecorder`, etc.

### 2.3 Container-Aware GOMAXPROCS (from Go 1.25)

On Linux in cgroup-limited containers (Kubernetes), the runtime now automatically defaults `GOMAXPROCS` to the cgroup CPU bandwidth limit rather than total host CPUs. This means the container will correctly throttle without needing the `uber-go/automaxprocs` library or manual `GOMAXPROCS` configuration.

**Action:** Confirm no manual `GOMAXPROCS` setting exists in the codebase (it does not — verified).

### 2.4 DWARF v5 Debug Info (from Go 1.25)

The compiler and linker now generate DWARF v5 debug info, reducing binary size and link time. Combined with the existing `-trimpath -buildvcs=false -ldflags="-s -w"` flags, the production binary will be slightly smaller.

## Phase 3: Code-Level Optimizations

### 3.1 Run `go fix` Modernizers

Go 1.26 completely rewrites `go fix` with dozens of modernizers that automatically update code to current idioms. Run it and review the diff:

```bash
go fix ./...
```

This is a read-and-review step — `go fix` should not change behavior. Inspect each change before committing.

**Expected areas of change:** Potentially `StatusOf` type assertion pattern (`err.(*AppError)` → may suggest `errors.As` if not already used), but the codebase already uses idiomatic patterns, so changes may be minimal.

### 3.2 Run `go vet` with New Analyzers

Go 1.25 added two new vet analyzers relevant here:

```bash
go vet ./...
```

- **`waitgroup`** — detects misuses of `sync.WaitGroup.Add`. Not currently used in this codebase, but good to verify.
- **`hostport`** — detects `fmt.Sprintf("%s:%d", host, port)` for network addresses and suggests `net.JoinHostPort`. The config package builds addresses via `":" + port` pattern (the `Addr()` method), which avoids this anti-pattern entirely. But running the check confirms nothing is missed.

### 3.3 Evaluate `testing/synctest` for Future Test Improvements

`testing/synctest` graduated to stable in Go 1.25. It provides `synctest.Test()` (runs tests in isolated "bubbles" with virtualized time) and `synctest.Wait()`.

**Current test state:** The project's tests use `httptest.NewServer` with simple synchronous request/response patterns. There is no concurrent testing beyond basic context cancellation tests. `testing/synctest` is **not immediately useful** for this codebase, but should be considered for:

- Future tests that need to verify timeout behavior without real sleeps
- Testing the `context.WithTimeout` propagation in `SearchAndSynthesize` more deterministically

**Recommendation:** Document as a future consideration; do not add now.

### 3.4 Evaluate `new(expr)` Language Feature

Go 1.26 allows `new(T)` to accept an expression: `new(expr)` creates a pointer initialized to the value.

**Current code:** The codebase uses a clean functional style without pointer-to-value patterns (config uses value types, not optional pointer fields). There are **no patterns** in this codebase that benefit from `new(expr)`.

**Recommendation:** No changes needed.

### 3.5 Consider `bytes.Buffer.Peek` (Go 1.26 stdlib)

`bytes.Buffer.Peek(n)` returns the next n bytes without advancing the buffer. This project does not use `bytes.Buffer` for JSON processing (it uses `json.NewDecoder`), so this is **not applicable**.
